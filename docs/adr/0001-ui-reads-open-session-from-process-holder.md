# ADR 0001. 설정 화면은 열린 세션을 프로세스 안 창구에서 읽는다

- 상태: 채택
- 날짜: 2026-09-10
- 관련: 이슈 #20 상태 카드와 알림 권한 흐름, 스펙 5절·8절

## 맥락

상태 카드는 연속 사용 시간을 라이브로 보여줘야 한다(스펙 5절). 그러려면 화면이 열린 세션의 시작
시각을 알아야 하는데, 세션 상태는 `TrackingService`가 리듀서를 돌려 메모리에 들고 있을 뿐이고
DataStore에는 `tracking_on`만 있다. 스펙 8절의 Room `sessions` 테이블은 아직 없다(복구 티켓 #27).

## 결정

`tracking` 패키지에 프로세스 범위 창구 `TrackingStatus`를 두고, 서비스가 리듀서에서 나온 새 상태를
`publish`하면 화면이 `sessionStartedAtMillis: StateFlow<Long?>`를 구독한다.

- 측정 상태 줄(꺼짐/켜짐)의 출처는 그대로 DataStore `tracking_on`이다. 강제 종료 뒤 서비스가 없는데
  `tracking_on`이 켜진 채 남는 상태에서도 사용자가 "측정 중지"로 빠져나올 수 있어야 한다(#19 코멘트).
- 연속 사용 시간의 출처는 이 창구다. 서비스가 없으면 null이고 카드는 "—"를 보여준다.

## 대안

- **Room `sessions`의 열린 행을 읽는다**: 스펙이 정한 최종 그림이지만 테이블·DAO·heartbeat가 함께
  와야 한다. 복구 티켓 #27의 범위이고, 상태 카드가 그것을 기다릴 이유가 없다.
- **DataStore에 `session_started_at` 키를 추가한다**: 스펙 8절 키 목록에 없는 키를 늘리는 일이고,
  세션 기록이 Room으로 갈 때 지워야 하는 중복 저장이 된다.
- **`bindService`로 서비스의 상태를 구독한다**: 전역 상태는 없지만 바인딩 수명 관리가 화면에 붙는다.
  DI 없는 단일 프로세스·단일 서비스 앱에서 얻는 것보다 잃는 게 많다.

## 결과

- 서비스가 죽고 화면만 새로 뜬 경우 카드는 "켜짐 + 세션 없음"을 보여준다. 어긋남을 되돌리는
  재동기화는 스펙 7절대로 #27·#28이 맡는다. 그때 이 창구의 출처가 Room의 열린 세션으로 바뀔 수 있다.
- `TrackingStatus`는 전역 가변 상태다. 쓰기는 `internal`이고 서비스만 부른다는 규약을 문서로 지킨다.

## 갱신 (#21, 2026-09-10)

세션 없음(`Phase.Idle`)이 생기면서 위 "켜짐 + —"가 "켜짐 + 세션 없음"으로 바뀌었다. 스펙 5절이
"켜짐이고 세션이 있으면 라이브, **세션 없으면 '세션 없음'**, 꺼짐이면 '—'"라고 정하고 있고, 이제
그 상태가 실제로 존재하기 때문이다. "—"는 측정이 꺼진 경우에만 남는다.

대가는 그대로다. 이 창구는 *세션이 없는 것*과 *서비스가 이 프로세스에 없는 것*을 구분하지 못해,
강제 종료 뒤 화면만 새로 뜬 경우에도 "세션 없음"으로 보인다. 화면에 보이는 문구가 달라졌을 뿐
어긋남의 성질과 그것을 없앨 주체(#27·#28의 재동기화)는 바뀌지 않았다.
