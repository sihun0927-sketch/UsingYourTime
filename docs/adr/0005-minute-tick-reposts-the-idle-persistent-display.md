# ADR 0005. 세션 없음의 `1분 tick`도 상시 표시를 다시 게시한다

- 상태: 채택
- 날짜: 2026-09-10
- 관련: 이슈 #29 도움말 섹션과 상시 표시 재게시, 스펙 3절 전이표, 스펙 4절 상시 표시

## 맥락

스펙 4절은 상시 표시의 재게시를 이렇게 정한다.

> 측정이 켜진 동안 항상 있다. Android 14+에서 사용자가 스와이프로 지우면 다음 갱신(`1분 tick`)에
> 다시 게시한다.

같은 절의 표에는 **세션 없음**("측정 대기 중")도 상시 표시의 한 상태로 들어 있다. `CONTEXT.md`의
상시 표시 정의도 "사용자가 지워도 측정이 켜져 있으면 다시 나타난다"고 적는다.

그런데 스펙 3절 전이표에는 세션 없음 · `1분 tick` 행이 없다. 세션 진행과 유예 중에만 있고, 그 둘은
문구가 매분 바뀌어서 갱신할 이유가 뚜렷했기 때문이다. 리듀서는 "전이표에 없는 (상태, 이벤트) 짝은
상태를 그대로 두고 효과도 내지 않는다"를 지키므로, 세션 없음에서 지워진 상시 표시는 다음 잠금
해제까지 돌아오지 않는다. 잠긴 채로 밤을 보내면 아침까지 없는 것이다.

재게시의 실행 경로는 하나뿐이다. `startForeground()`에 같은 알림 id로 다시 게시하는 것이고, 서비스는
리듀서가 낸 `UpdatePersistentDisplay` 효과를 받을 때만 그 호출을 한다(코드 스타일 4번). 그래서 이
공백은 "다시 그릴 것이 없다"가 아니라 "되살릴 길이 없다"가 된다.

## 결정

`1분 tick`은 **측정이 켜진 세 국면 모두**에서 상시 표시 효과를 낸다. 세션 없음에서는 바뀔 것이
없는 대기 문구를 그대로 다시 낸다.

전이표에 행을 하나 더 읽는 것이다.

| 현재 상태 | 이벤트 | 다음 상태 | 하는 일 |
|---|---|---|---|
| 세션 없음 | `1분 tick` | 세션 없음 | 상시 표시를 대기 문구로 다시 게시 |

곧 갱신 주기를 "내용이 바뀔 때 다시 그리기"가 아니라 "측정이 켜진 동안 매분 상시 표시가 있음을
확인하기"로 읽는다. 4절의 "측정이 켜진 동안 항상 있다"가 그 문장이다.

## 대안

- **서비스가 매 tick에 지워졌는지 확인하고 되살린다**: `getActiveNotifications()`를 훑어 상시 표시가
  없으면 다시 게시하는 쪽. 리듀서 밖에 "무엇을 게시할지" 아는 코드가 생기고(코드 스타일 4번 위반),
  마지막 내용을 서비스가 따로 들고 있어야 한다. 얻는 것은 매분 한 번의 `notify` 절약뿐이다.
- **세션 없음에서는 재게시하지 않는다**: 스펙 4절 표의 세션 없음 행과 `CONTEXT.md`의 상시 표시
  정의를 어긴다. 사용자에게는 "지웠더니 측정이 꺼진 것처럼 보이는" 상태가 남는다.
- **`FLAG_NO_CLEAR`나 다른 플래그로 지워지지 않게 만든다**: Android 14+에서 ongoing 알림의 스와이프
  해제는 앱이 막을 수 없다(스펙 8절 표). 막을 수 있다 해도 사용자가 지운 것을 되돌리는 쪽이 맞다.

## 결과

- 세션 없음에서도 매분 `startForeground()`가 한 번 돈다. 내용이 같은 알림이라 소리·진동은 없고
  (`setOnlyAlertOnce`), 알림 창의 정렬도 흔들리지 않는다.
- 재게시는 상태를 바꾸지 않는다. 세션 없음 · `1분 tick`이 내는 효과는 상시 표시 하나뿐이라 임계값
  알림·세션·heartbeat에 닿지 않는다(heartbeat는 세션 진행에서만 나간다, 스펙 7절).
- 측정 꺼짐은 그대로 아무 효과도 내지 않는다. 게시할 상시 표시가 없고 서비스도 없거나 내려가는
  중이다.
